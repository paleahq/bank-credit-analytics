# Дашборд в Power BI: пошаговая сборка

Собирается за 2–3 часа. Всё, что нужно — файлы из `data/`.

## 1. Загрузка и модель

`Получить данные → Текст/CSV` → загрузить все 5 файлов из `data/`.

В `Модель` связать:

| Из | Поле | В | Поле | Тип связи |
|---|---|---|---|---|
| applications | client_id | clients | client_id | многие-к-одному |
| loans | app_id | applications | app_id | один-к-одному |
| payments | loan_id | loans | loan_id | многие-к-одному |

Создать таблицу дат: `Календарь = CALENDAR(DATE(2024,1,1), DATE(2026,1,1))`
и связать с `applications[apply_date]`. Пометить как таблицу дат.

## 2. Меры (DAX)

```dax
Заявок = COUNTROWS(applications)

Одобрено = CALCULATE([Заявок], applications[decision] = "Одобрено")

Выдано = SUM(applications[is_issued])

Approval Rate = DIVIDE([Одобрено], [Заявок])

Take-up = DIVIDE([Выдано], [Одобрено])

Сквозная конверсия = DIVIDE([Выдано], [Заявок])

Объём выдач = CALCULATE(SUM(applications[approved_amount]), applications[is_issued] = 1)

Средний чек = DIVIDE([Объём выдач], [Выдано])

Расходы = SUM(marketing_spend[marketing_spend])

CAC = DIVIDE([Расходы], [Выдано])

CPA заявки = DIVIDE([Расходы], [Заявок])

Кредитов с дефолтом 90+ =
CALCULATE(
    DISTINCTCOUNT(payments[loan_id]),
    payments[days_past_due] >= 90
)

Дефолт 90+ % =
DIVIDE([Кредитов с дефолтом 90+], DISTINCTCOUNT(loans[loan_id]))

NPL 30+ % =
DIVIDE(
    CALCULATE(DISTINCTCOUNT(payments[loan_id]), payments[days_past_due] >= 30),
    DISTINCTCOUNT(loans[loan_id])
)

Объём в дефолте =
CALCULATE(
    SUM(loans[principal]),
    FILTER(loans, CALCULATE(MAX(payments[days_past_due])) >= 90)
)
```

## 3. Страница 1 — «Воронка и каналы»

- **KPI-строка сверху:** Заявок · Approval Rate · Take-up · Выдано · Объём выдач · Средний чек
- **Воронка** (визуал «Воронка»): Заявок → Одобрено → Выдано
- **Гистограмма:** Approval Rate и Take-up по каналам (две меры рядом — сразу видно, что онлайн проваливается на take-up, а не на решении)
- **Линейный график:** Заявок и Выдано по месяцам, вторая ось — сквозная конверсия
- **Срезы:** Продукт, Регион, Период

## 4. Страница 2 — «Экономика привлечения»

- **KPI:** Расходы · CPA заявки · CAC кредита · Расходы к объёму, %
- **Точечная диаграмма:** ось X — CAC, ось Y — Дефолт 90+ %, размер точки — Объём выдач, точки = каналы.
  Это главный визуал проекта: он показывает, что дешёвый канал может быть самым дорогим по риску
- **Столбчатая:** CAC по каналам с линией среднего
- **Матрица:** канал × продукт, значение — CAC

## 5. Страница 3 — «Риск и портфель»

- **Тепловая матрица (vintage):** строки — месяц выдачи, столбцы — месяц жизни (1–12), значение — NPL 30+ %
- **Столбчатая:** Дефолт 90+ % по каналам и по диапазонам дохода
- **Круговая/столбчатая:** структура причин отказа
- **Карта Казахстана:** объём выдач по регионам, цвет — дефолт 90+ %
- **Таблица ABC:** сегмент, клиентов, доля объёма

## 6. Оформление

- Единая палитра: 1 акцентный цвет для «хорошо», 1 для «риск», остальное серое
- Все проценты — с одним знаком после запятой, суммы — в млн ₸
- Заголовок каждого визуала формулируй как вывод, а не как название:
  не «CAC по каналам», а «Мобильное приложение — вдвое дешевле отделения»
